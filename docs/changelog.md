### v26(B1完全解決+まれにモード変更の原因修正 — 現行)
- **ユーザー実機発見(2026-09-26)が出発点**: 日本語モード中に左Shiftホールド→Caps→**Shiftを先に離す→Capsを離す**(500ms内)で高確率で英字モード(RGB青+IME英字)。これはB1の「LTタップキーコードが発火しない」中で唯一生きていた経路だった — Shiftを離すと `PERMISSIVE_HOLD` でFUNC層が確定(ホールド判定)→Caps離しで層が落ち→v23のフォールバック(無変換0x8B+青+NICOLAオフ)が発火
- **B1完全解決**: QMKの `LT()` に頼らず **自前のhold/tap実装(KC_CAPSFUNC)** に変更。押下→FUNC層ON/リリース→**500ms未満&FUNC層キー未使用**なら無変換0x8B+青+NICOLAオフ=タップ扱い。タップ検出をQMKのtapping機構から完全に切り離したので、B1の「タップキーコードが発火しない」問題は構造的に消滅
- **二重発火防止**: 層ON/OFFを自前で呼ぶため `layer_state_set_user` 側の旧フォールバックを削除(残すと0x8Bが2連発)
- **nicola_pending無条件セットを修正(LSHIFT/RSHIFT両ブロック)**: 旧コードはテーブル未マッチのキー(Shift+Caps等)でも押した瞬間に `nicola_pending = true` を立てていた(v9以来の潜みバグ)→未確定残留→**後の親指押下で無変換(0x8B)/変換(0x8A)が飛ぶ=「まれにモードが変わる」のもう一つの原因**。マッチした時だけセットに変更
- **Caps+ESC/FL+Mへの影響なし**: モード切替コンボは無線モジュールがマトリクスレベルで検出(keycode非依存)を確認
- v25(マスター役割の自動判定)の内容も本ビルドに全て含まれる

### v25(役割の自動判定化 — 右半身ソフトDFUの正解・現行)
- **根本原因の発見**: keymap.c末尾の `is_keyboard_master()` オーバーライドが B9ピン(左右判別用)を読んで役割を強制していた → **右が永久にスレーブ固定**になり、右側でのQK_BOOT発火・RST_R経由が全て不能だった
- **修正**: オーバーライドを削除 → QMK標準の `SPLIT_USB_DETECT`(ChibiOS/ARMでデフォルト有効)が復活し、**マスター=USBを挿した半身**に自動決定される
- **効果**: **USBを右半身に挿げ替えるだけで右がマスター** → FL+M(またはCaps+ESC)で右がそのままDFUに = **ピンホール・スイッチ・EEPROMフラグすべて不要**
- **左右判別(B9)はキー配列のミラー用として存続**(keyboard.json の handedness.pin) — 役割とは別物
- **注意**: 無線モジュールはマスター側から制御されるため、USB右挿し中は無線機能が動かない可能性(有線専用運用では無問題)。普段使い(左挿し)では何も変わらない
- Split70: 公式QMKにマージ済み。同構成なら同手法が転用可能

### v22(右半身ソフトDFU・現行)
- **発見**: `epomaker_split65.c` の `user_sync_mms_slave_handler`(1632行)がマスター→スレーブRPCを既に運用中(cmd 0x55=マルチモード同期・0xDD=EEPROMリセット、housekeepingから2秒毎)。ここに **cmd 0xBB = `bootloader_jump()`** を追加
