## 2. 変更済みキーマップ表

### 2.1 英字モード(ベース層 _QWERTY)

```
 ESC  1  2  3  4  5      6  7  8  9  0  -  =  BSPC  MUTE
 TAB  Q  W  E  R  T      Y  U  I  O  P  [  ]  DEL   ←(旧INT1)
 C→英字 A  S  D  F  G    H  J  K  L  ;  '  ENT  PGUP
 LSFT Z  X  C  V  B      N  M  ,  .  /  RSFT UP  PGDN
 LCTL LCMD LALT  [L-SP(2連打→日本語)] [R-SP] DEL FL  RCTL ← ↓ →
                                      ↑(旧DEL)
```

- `C→英字` = CapsLock 位置。**タップで英字モード、ホールドでファンクション層**
- `LALT` = 左ALT位置。**タップ/ホールドとも素の Alt**
- 親指行の￥/ろ位置は **DEL に戻った**(￥/ろはベース層からは一旦廃止)
- `[L-SP(2連打→日本語)]` = 左スペース。**1タップ=スペース**(即時、ゲームでも遅延ゼロ)。**300ms内の2連打で日本語モードへ**(2発目のスペースはBackspaceで自動撤去)。ホールド=スペースのまま
- `[R-SP]` = 右スペース。単独押しでスペース入力
- **INT1(￥/ろ)と DEL を入れ替え済み**:**日本語モードも含めて全モード共通**。右端上段=DEL、親指付近=INT1
- 各文字キーは**刻印通りの文字**。jtu が US刻印→JIS PC出力に変換(Shift+2=@、Shift+7=&、Shift+8=*、Shift+9=(、Shift+0=)、[¥]=[]、=はShift+半角/-、;はそのまま、'=Shift+7 位置など)

### 2.2 日本語モード(NICOLA層)— 3分割打鍵表

**操作方法**:
- **単独打鍵** = キーを1つだけ押す
- **左親指同時打鍵** = L-SP(左スペース)を押しながらキーを押す
- **右親指同時打鍵** = R-SP(右スペース)を押しながらキーを押す
- 出力はローマ字(IMEに送る文字列)。`xya` など `x` 付きは小文字(ゃゅっ等)
- **親指キー単独押しは状態で切替**(タイムアウト後):
  - **未確定(かな未変換)あり** → 左親指=**無変換**(ひらがな⇔カタカナ⇔半角カタカナ切替)、右親指=**変換**(漢字変換/候補切替)
  - **未確定なし(通常時)** → スペース
- ファームはIME状態を直接見られないため、「NICOLAでかなを出力した直後」を未確定と判定。Enter/ESC/矢印/Delete/BS/モード切替で未確定なしに戻る。候補選択中に実スペースを入れたい場合は一度Enterで確定してから
- **DEL と INT1 の位置は英字モードと同一**(全モード共通で入れ替え済み):右端上段=DEL、親指付近=INT1

## 2.5 DFUモード(書き込みモード)への入り方

### FLキーの場所

**FL = 親指行の右側、R-SP(右スペース)の隣のキー**(`MO(_FL)`)。押している間だけFL層(BT設定・RGB調整・電池表示)に切り替わる。

```
 ... [左スペース] [右スペース] [DEL] [FL] [RCTL] ...
                      ↑ここ     ↑FL(このキーを押しながらM)
```

### DFUへの入り方(3方法)

| 方法 | 操作 | 使い分け |
|---|---|---|
| **A. FL + M**(v16以降) | FLキーを**押しながら M** → すぐDFUへ | **普段はこれ**。裏返し不要 |
| **B. 物理リセットスイッチ** | PCB裏のリセットスイッチを押す | キーマップ依存なし。初回や不具合時 |
| **C. スペース裏ショート** | スペース裏の2か所の穴(金属メッキ電極)をショートしたままUSB挿入。**右半身はさらにシフト裏のスイッチ操作も必要** | A/Bが使えない時・記事の元手順 |

- **v17(2026-09-25)**: モード切替キーの冪等化。①CapsLockタップは日本語モード時のみ「無変換+英数」を送出(英字モード中の再送出で無変換=IMEオンが効き、日本語に戻る+RGB不一致になるバグを修正) ②Caps+L-SP(KC_EISU)も同様に冪等化 ③Caps+R-SP(KC_KANA2のFUNCパス)とL-SPダブルタップは日本語モード時に「変換+かな」を送らない(未確定文字列なしの変換キー=確定済み文節の再変換防止)。ファーム以外の変更なし。
### 半身ごとの書き込み手順(最終確定版)

**ルール(実機検証済み): マスター/スレーブはハード配線で固定。キーのコンボ(FL+M / Caps+BRK / Caps+ESC)は左半身(マスター)でしか発火しない。右半身はキーではDFUに入らない。**

1. 左右のブリッジケーブルを外す(いつものピンホール作業と同じ形にする)
2. 左半身: USBを左のType-Cに挿す → **FL+M**(または物理スイッチ/ピンホール)→ DFU認識 → Flash → **Flash complete** → **Exit DFU**
3. 右半身: USBを**右のType-Cに挿し替え** → **シフト裏のスイッチを操作した状態でUSB挿入**(=いつもの右半身の手順。記事の手順どおり。物理リセットスイッチ/ピンホール短絡の併用でも可)→ DFU認識 → Flash(**ファイル欄が split65_v20.hex か再確認**)→ Flash complete → **Exit DFU**
4. USBを左へ戻し、ブリッジ再接続で完了

### DFU書き込みの仕組み(なぜ「指定なし」で左右別々に書けるか)

- キーボードがDFUに入ると、PCからは **「WB32 DFU(WestBerry製・無線内蔵チップ)」というUSBデバイス1台**として見える(もう片方の半身は通常キーボードのまま)
- QMK Toolbox は**接続中の DFU デバイスを自動検出し、その1台に書き込む**。デバイスが1台しか無いので「書き込み先の指定」は暗黙に成立する
- 左を書き終えると左は再起動して DFU が消える → 次に右を FL+M で DFU に入れると**今度は右だけが DFU デバイス** → 同じ hex が右に書かれる
- **左右同時に DFU になることはない**(ブリッジ経由では1台ずつ)ため、「2回書き込む」だけで両方に確実に届く。誤って逆側に書いても中身は同一 hex なので実害ゼロ
- 注意: 他の STM32 系デバイス(別キーボード・マイコンボード)を繋ぎっぱなしにしてると、そちらが DFU 中ならそちらに書かれる。作業時は Split65 以外の USB デバイスを外すのが安全

### Auto-Flash の使い方

- QMK Toolbox の設定で **Auto-Flash** を有効にすると、**DFU デバイスを検知した瞬間に選択中の hex を自動書き込み**する
- フロー: 左 FL+M → 自動書き込み → 右 FL+M → 自動書き込み。**Flash ボタン押下すら不要**、2回の書き込みで完了
- 注意: 検知した DFU デバイスは問わず書き込む(左右同一 hex なので問題なし)。ただし**日常運用中に誤って FL+M すると即再起動+書き込みが始まる**ため、**Auto-Flash は書き込み作業時だけ有効化し、普段はオフ運用**を推奨

## 3. 書き込み手順(QMK Toolbox)

1. [QMK Toolbox](https://qmk.fm/toolbox) をWindowsにインストール
2. **DFUモードに入れる(物理)**:
   - 左半身: スペース裏の2か所の穴(金属メッキ電極)をピン等でショートした状態でUSB接続
   - 右半身: スペース裏のショートに加えて、**シフト裏のスイッチ操作**も必要
3. QMK Toolbox で `leo_epomaker_split65_nicola.hex` を開き、Flash を実行
4. **左右両方の半身に同じhexを書き込む**(左右用の違いはない)
5. 書き込み後、USBを再接続して動作確認

- **v18(2026-09-25)**: FL+Mの設計ミス修正。Mキーは右半身のキーのためFL+Mは右半身でしかDFUに入らなかった(=書き込みを右半身2回分繰り返しても左半身は更新されない)。_FUNC層のBRK(Pause)をQK_BOOTに変更し、Caps+BRKで**左右どちらの半身でも**DFU移行可能に。FL+Mも併用可(※「右半身」とあったのは誤記。実際は左=マスターでのみ発火)。
- **v19(2026-09-25)**: ①モード切替の決定版。CapsLockタップ・Caps+L-SP=「英数」のみ送出(無変換を廃止: MS-IME既定で無変換=IMEオンが2度押しバグの原因)。Caps+R-SP・L-SPダブルタップ=「かな」のみ送出(変換を廃止: バッファ空の変換キーが文節再変換の原因)。これで全切替が冪等になり、ファーム/IME状態のズレも自動修復される。②_FUNC層のEsc位置キー(バッククォート)にもQK_BOOTを追加(Caps+`)。**重要な訂正: キーマップ上のQK_BOOTは、PCに接続している側(マスター)半身でしか発火しない**。分割キーボードのスレーブ半身はキー処理を自分では行わず(マスターが全部処理する)ため、MやBRKなど物理的な位置にかかわらず、FL+M/Caps+BRK/Caps+`は左半身(マスター)で発火する(右はハード的にスレーブ固定 — v20実機で確定)。**スレーブ半身(普段ブリッジ側)をDFUに入れる方法は物理リセットスイッチかピンホール短絡+その半身のUSBポートにPC直挿しのみ**。
- **v21(2026-09-25)**: 診断版。FUNC層(Capsホールド)に5つのIME診断キー追加(**物理キー・US刻印**): **Fn+P**=無変換(0x8B) / **Fn+[**=変換(0x8A) / **Fn+\**=英数(0x91) / **Fn+;**=かな(0x90) / **Fn+/**=Alt+半角全角。該当キーを押してIMEアイコン(A/あ)が動くか観察 — 動いたキーがその環境の「効くキー」。診断後はv22で確定実装。

- **v20(2026-09-25)**: RGBインジケータ修正。モード切替時(Caps単押し/Caps+L-SP/Caps+R-SP/L-SPダブルタップ)にRGB Matrixのエフェクトを**単色モードへ強制切替**してから色を設定(虹色などのアニメーション中は色指定が表示に反映されない = v19まで「切替してもRGBが変わらない」ように見えた原因)。noeeprom版のため起動直後はEEPROM保存のエフェクト(虹色等)のまま、最初のモード切替で単色インジケータに変わる。※**Fn+Q は RGB ではない — BT1(Bluetooth モード1への切替)キーだった(誤指示の元凶)**。RGBエフェクト巡回は**Fn+Tab**、ON/OFFはFn+C。DFU入口の最終確定: **右半身(スレーブ)はキーコンボではDFUに入らない**(USBを挿げ替えてFL+Mしても不発=実機検証)。右は必ず物理リセットスイッチ/ピンホール短絡で書き込む。
### 書き込み完了の見分け方と、やりがちな罠(v17〜v19検証で確定)

- **正規手順**: FL+M(またはピンホール)でDFU移行 → Flash → ログに「Flash complete」→ **「Exit DFU」を押して再起動**。このボートローダーは自動再起動しない
- **バックライトは書き込み成否の判定に使えない**: ファームを書き換えても EEPROM の RGB 設定(虹色)は消えないので、再起動後も見た目は変わらない=**変わらなくて正常**。DFU中だけLEDが消え、Exit DFU で復帰するのも正常
- **罠1: 古いhexを選び続ける**: ビルド番号が違っても出力ファイル名は常に `leo_epomaker_split65_nicola.hex`。QMK Toolbox は前回選んだファイルを覚えている。**バージョンごとに一意な名前(例: split65_v20.hex)で保存し、Flash前に Toolbox のファイル欄を必ず確認**する(v17時にプロジェクト初期の古いhexを書き込んだ疑いが実際に発生)
- **罠2: 1回のDFU移行で2半身書いたつもりになる**: **DFUに入ったのは1半身だけ**なので、その間に何回Flashしても**同じ半身に上書きされる**。両半身を更新するには「DFU移行→Flash→Exit DFU」を**半身ごとに2回繰り返す**
- 半身ごとのDFU入口(**最終確定・実機検証済み**): キーのコンボ(FL+M / Caps+BRK / Caps+ESC)は**左半身(マスター)でのみ発火**。右半身(スレーブ)はハード配線で役割が固定のためキーではDFUに入らない(**実機確認: USBを右に挿げ替えてFL+Mしても不発**)。→ **右半身の書き込みは必ず物理リセットスイッチ or ピンホール短絡 + 右のUSBポート直挿し**(右半身は**シフト裏のスイッチ**を使うのが実績ある手順 — このスイッチはDFU/ブート用のハード系スイッチで、マスター/スレーブの切り替えではない: ファームの役割判定は基板ピンの配線で固定)。MやESCの物理的な左右は関係ない(スレーブ半身はキー処理をマスターに任せるため)。→ どちらの半身を更新したい時も、その半身にUSBを直挿ししてからコンボ。キーで入らない古いファームの半身だけ物理リセットスイッチ/ピンホール短絡

### トラブルシュート: 「モード切替が効かない/RGBが虹色のまま」時のEEPROMリセット(EE_CLR)

この機種はマルチモード(USB/BT/2.4G)対応で、**接続モードやRGB状態はEEPROMに保存される(ファーム書き込みでは消えない)**。FL層のBT切替キー(Fn+Q/W/E=BT1/2/3、Fn+R=2.4G)を押すと**USB接続中でも無線モードの状態に遷移**し、以後の挙動が変わることがある。ファームを書き直しても症状が消えない場合は EEPROM 状態の疑い。

**リセット手順**: **Capsをホールド(FUNC層) → EE_CLR キー**(FL層/FUNC層のF12の隣=旧DEL位置)を1回タップ → RGBが一瞬消えて再起動する。その後モード切替・RGB連動を再テストする。EE_CLR で BT/2.4G/RGB の保存状態が工場出荷に戻る(キーマップはファーム内蔵なので影響なし)。

### 右半身へのソフト書き込み(v22以降 — スイッチ/ピンホール不要)

1. bridge接続・USBは左(普段どおり)で、**Capsホールド → FUNC層の **TAB行の右端キー(DEL表示)**=RST_R** を押す
2. 右半身がブートローダーへ再起動する(bridgeリンクは切れるが正常)
3. **USBケーブルを右のType-Cへ差し替え**(右は電池駆動でDFU維持)→ Toolboxに WB32 DFU 出現

### Caps単押し(B1)v26で解決 — 「まれに」を「常に」に

- **あなたの発見(左Shift→Caps→Shift先離し→Caps離しで高確率)が決定打**。原因はQMKのLT()のタップ検出がこの基板で発火しないこと。v26ではCapsをQMKのLTに頼らず自前実装(KC_CAPSFUNC)にした: **Caps押下→0.5秒以内に離す&他のFUNCキー未使用なら英字モード(無変換0x8B)+RGB青**
- 普通の短押しだけでOK。Shiftを先に離すテクニックはもう不要(やってても問題ない)
- 日本語モード中の親指で「まれにモードが変わる」現象もv26で修正(pending残留バグ)
- 確認項目: Caps短押し→青+英字 / Caps長押し→FUNC層(従来通り) の両立

## 4. 注意事項(必読)

- **無線は使えなくなります**。この改造ファームは 2.4GHz/Bluetooth 非対応。有線運用専用。書き戻しても無線は復帰しないので注意
- 書き込みは**自己責任**で。ハードの製造時期により差がある可能性は元記事の通り
